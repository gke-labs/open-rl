Does rank 1 keep up?

Reproducing the reinforcement-learning claim from LoRA Without Regret on Open-RL · 2026-08-26

Thinking Machines report that for reinforcement learning, LoRA matches full fine-tuning even at rank 1. We ran all three arms concurrently on one Kubernetes cluster. Over 50 steps of GSM8K RL, rank 1 finished within 0.013 of full fine-tuning — roughly a tenth of the run-to-run noise.

The claim

A policy gradient extracts on the order of one bit per episode, against O(tokens) for supervised learning — about a thousandfold less information per token. The argument follows: an adapter holding millions of parameters has ample capacity for an RL run carrying a few hundred thousand bits, so rank should not matter.

Setup

Three arms on Qwen/Qwen3-0.6B, identical in dataset, group size, batch, token limit, temperature and step count. Only the mode and rank differ. Learning rates keep the paper’s ~10× ratio — equalising them would compare each arm at a different distance from its own optimum.

What this does not show

At 3,200 episodes this run is about 1% of the paper’s MATH experiment (~320,000 episodes). By their own information argument, capacity binds only as episode-bits approach adapter parameters — we are two to three orders of magnitude away. This result shows rank 1 trains and tracks; it cannot test the capacity claim.

One seed per arm. The spread bounds within-run noise, not seed-to-seed variance, so a gap of this size is not evidence either way. And the authors deliberately used Llama for GSM8K because Qwen’s math-heavy pretraining confounds the measurement — we used Qwen.

The systems half

Three concurrent RL jobs ran on four L4 GPUs. Full fine-tuning held a GPU to itself at 42s per step; the two LoRA arms shared one and took 88s each — almost exactly 2×, so the difference is time-slicing rather than LoRA being slower. Two adapters of different rank coexisted on one device throughout, which is what makes the equal-performance result cheap: the same answer on half the hardware.
